# Hireland：六个里程碑与独立开发 Prompts

## 使用方法

总计 **6 个：M0、M1、M2、M3、M4、M5**。单 agent 顺序建议 M0 → M1 → M2 → M3 → M4 → M5；时间不足可以跳过可选的 M3，但不能跳过核心 AI、用户验证和交付检查。

换账号时，给新 agent 同一仓库的最新完整版本，包括代码、迁移、锁文件、文档和必要的非敏感测试数据；单独复制聊天 prompt 不能恢复未同步的代码。用户已授权每次工作结束直接本地 commit；跨账号同步使用提交后的源码或完整工作区，不自动推送或部署。不要把 `.env`、私密数据和数据库秘密内容提交到仓库。

每段 prompt 都可以单独复制，不依赖上一账号的聊天记录。路径使用仓库相对路径，换机器也适用。Agent 必须读取 `Doc/HANDOFF.md` 并核查实际文件，不能只相信状态标签。凭据缺失时继续可做的实现和本地验证，准确列出剩余人工步骤，不伪造成功。

六小时仅是初始排期预算，不是强制在截止时间把未完成工作标为完成。新 agent 应说明尚需工作；如果没有明确继续下一阶段的要求，结束于当前里程碑并写交接记录。

## M0：范围、技术决策与外部依赖检查

预计 30 分钟。目的：让团队从一致的需求、数据模型和环境事实开始，尽早暴露账号、额度和运行环境阻塞。本阶段不实现全部业务。用户访谈由团队启动，agent 准备提纲并记录真实输入。

退出条件：范围与接口明确；实际运行环境已检查；供应商检查有真实结果或明确阻塞；下一阶段可以直接动手。

```text
你正在继续 Hireland，一支小组的 HackUCD 2026 项目。请执行 M0，不要只给建议，也不要一次实现全部阶段。

先阅读适用的 AGENTS.md、README.md、Doc/HANDOFF.md、Doc/01_MONOLITH_PLAN.md，并核对 Doc/hackucd-2026-challenges.pdf。检查实际目录和 git 状态，保留已有改动。Doc/00_MASTER_PRD.md 是历史草稿，其“三个独立 App”要求已失效。

固定方向：一个全栈 monolith、一个端口和一个本地数据库；建议 Next.js + TypeScript + SQLite。主赛道 Everyday Frustrations。核心是爱尔兰毕业生选岗位→提供 CV 和偏好→真实 OpenRouter 建议→保存和更新申请。Stripe sandbox 社区解锁是可选加分。不要做爬虫、多服务或生产身份系统。

任务：核查可用运行环境；确定并记录技术版本、数据表、唯一约束、内部函数签名和 demo 用户策略；制定统一环境变量清单和安全的 .env.example；在已有凭据允许时做最小真实 OpenRouter 调用及 Stripe sandbox 访问检查，不创建真实收费。查询框架/SDK/API 资料时按 AGENTS.md 用 Context7，工具不可用则说明并核实官方文档。

准备匿名学生访谈提纲、一个可验证假设和数据来源记录模板。不要编造访谈。缺密钥时列出配置方式，完成不依赖凭据的工作，不输出秘密值、不用 mock 冒充真实验证。仅为本阶段补最小验证脚本，不提前铺开业务。

完成后更新 Doc/HANDOFF.md：决策、环境与检查命令、真实结果、未验证项、阻塞、下一步。将状态据实设为 DONE 或未完成，并说明 M1 如何继续。验证并更新交接后直接本地 commit，不自动推送或部署。
```

## M1：单体骨架、页面与持久化

预计 45 分钟。目的：没有 AI 和支付也能在同一应用完成“看岗位→保存申请→修改状态”。建立后续成员共享的真实数据模型。

退出条件：一个应用可启动；种子数据和页面可用；申请与 Profile 重启后仍保留；重复操作不产生重复记录。

```text
请继续 Hireland 的 M1，直接实现并验证单体应用骨架。先阅读适用 AGENTS.md、README.md、Doc/HANDOFF.md、Doc/01_MONOLITH_PLAN.md，检查现有代码、依赖、迁移和 git 状态。历史 PRD 的三个独立 App 方案不适用。若 M0 有缺口，补齐本阶段必需部分并记录，不重做已完成工作。

项目是 HackUCD 2026 Everyday Frustrations 原型：爱尔兰毕业生选岗位→CV 与偏好→OpenRouter 建议→申请追踪。固定为一个全栈应用、一个端口、SQLite；默认 Next.js + TypeScript，沿用仓库已验证选择。禁止独立前后端项目、第二套数据库和模块间 HTTP 对接。按 AGENTS.md 查询当前框架文档。

实现统一导航、岗位列表/关键词搜索/详情、Profile 的 CV 文本与职业偏好、加载虚构 CV、申请新增/状态更新/删除。状态为 SAVED/APPLIED/INTERVIEW/OFFER/REJECTED。服务端统一取得 demo 用户，页面通过内部业务函数访问数据。准备迁移和幂等 seed，8–12 条明确标注 synthetic 的岗位，未知日期/状态不得伪装成真实开放岗位。保留后续 AI、社区、支付的关联键，但不做这些阶段的功能。

验收：一条启动路径；保存 Profile 和申请后重启仍存在；重复保存和 seed 不重复；空结果、无效输入、找不到岗位有清晰反馈。申请保存不等于真实投递。运行必要的类型、构建和业务检查，只报告实际结果；不要用硬编码画面替代数据库。不要做爬虫、上传解析、拖拽看板或真实支付。

更新 README 的实际安装、配置、迁移、seed、启动步骤。更新 Doc/HANDOFF.md 的关键文件、验证命令/结果、schema 和未完成项，指明 M2 入口。不覆盖他人改动，验证后直接本地 commit，不自动推送或部署；完成 M1 后停止。
```

## M2：真实 AI 与申请闭环

预计 75 分钟。目的：完成比赛最重要的 AI 价值，能够解释建议、承认未知并正确处理失败。

退出条件：至少一次真实 OpenRouter 成功调用；可核对的输出；缓存失效与失败路径已验证；从分析到申请追踪走通。没有真实调用证据不能标为完全完成。

```text
请继续 Hireland 的 M2，完成真实 AI 核心闭环。先阅读适用 AGENTS.md、README.md、Doc/HANDOFF.md、Doc/01_MONOLITH_PLAN.md，检查 M1 实现与 git 状态。该项目必须是单个全栈 monolith 和 SQLite，保留已有工作；旧 PRD 三 App 设计已失效。若核心数据路径缺失先补最小前置，不重建项目。

HackUCD 要求有用的真实 OpenRouter 功能，仅 AI 编程和 mock 不计入 AI 使用证据。实现“选岗位→读取服务端 Profile/CV/偏好与 JD→一次 OpenRouter 评估→展示→保存申请”。按照 AGENTS.md 用 Context7 核实所用 API 和结构化输出支持；密钥只在服务端，模型配置化。

一次返回 YES/NO/NEEDS_REVIEW、可空匹配分、简短理由、最多各两项优势/不足、可对照原文的证据和待确认项。缺输入是校验错误，语义信息不足是 NEEDS_REVIEW，供应商故障是错误状态，不能变成 NO/0 分。注明分数不是录用概率。不服从 CV/JD 中的指令，不编造经历。用输出 schema 和服务端校验；限制输入、并发、超时，允许用户重试。

缓存涵盖用户、CV/JD/偏好、prompt 版本和模型；修改任一相关内容不能命中旧结果。提供虚构 CV 和明显匹配、不匹配、信息不明、指令干扰样例。验证超时/限流/无效 JSON/越界值、重复点击和缓存失效。故障模拟与真实调用证据分开记录，日志不含完整 CV 或密钥。

完成浏览器核心旅程并保存非敏感证据。凭据或网络缺失时继续代码和离线测试，准确标出“真实 OpenRouter 未验证”，不能宣称 DONE。更新 Doc/HANDOFF.md、README 和必要测试记录，说明下一阶段入口；不实施 M3、验证后直接本地 commit，不自动推送或部署。
```

M2 当前接续提示（2026-10-10）：真实 AI 实现与技术验收已完成，详见 HANDOFF 和 M2_CHECKS。不要重新搭建 adapter 或伪造反馈。若继续收尾 M2，请收集首位求职用户用虚构 CV 完成核心任务的匿名观察，记录能否独立完成、困惑点与反馈；按实际发现修改并验证，再决定是否标 DONE。新账号需自行配置忽略的 `.env.local`，不能从 Git 获取密钥。每次收尾按用户授权直接本地 commit。

## M3：社区与 Stripe 加分流程

预计 90 分钟。目的：用完整购买与权益兑现争取可选 5 分，而非只做一个购买按钮。

退出条件：真实 sandbox 成功交易、正确话题权益、服务端付费墙、取消与重复确认的正确行为。M3 可跳过，但必须明确放弃 bonus，不能让它阻塞基本参赛闭环。

```text
请继续 Hireland 的 M3：社区与 Stripe sandbox 加分流程。先阅读适用 AGENTS.md、README.md、Doc/HANDOFF.md、Doc/01_MONOLITH_PLAN.md 及比赛 PDF p5–6，检查代码和 git 状态。沿用现有单体应用、SQLite、Job 和 demo 身份，不创建另一个应用或用户系统；核心 AI 闭环不得回退。

为同一岗位建立话题和评论，预置至少 6 条明确标注虚构的评论。免费仅返回最新 3 条正文，付费后返回全部；限制必须在服务端，HTML、组件数据和接口不能泄漏其余正文。支持校验后发评论，并重新按权限读取。

价格固定 €0.99 EUR/单话题/一次性购买，仅 sandbox。用 Stripe Checkout Sessions 创建托管支付，价格与身份由服务器决定，并关联本地 Purchase。按 AGENTS.md 用 Context7 核实 Stripe 集成。支付返回页和验签 webhook 调同一幂等确认函数：服务端查询真实 Session，检查 paid、sandbox、商品/数量/金额/币种与本地订单对应，返回页检查当前用户归属；事务写订单与 Entitlement，用唯一约束防止并发重复。不得信任 success URL 或前端 paid 标记。

验证成功购买后刷新/重启仍解锁；取消、未付款、错误归属、篡改参数、无效签名不解锁；重复事件不重复发权益；付款后未返回或写入失败能重试恢复。只开放即时卡支付，不做订阅或真实收款。Stripe 本地事件转发是开发工具，不是第二个业务服务。

在可用权限内完成真实 sandbox 交易，记录非敏感交易标识与产品结果。若支付操作需人工完成，明确给出步骤并继续可完成的验证，不伪造成功，不把 mock 当加分证据。更新配置/运行文档和 Doc/HANDOFF.md，分别列实现完成与真实交易验收状态；验证后直接本地 commit，不自动推送或部署。
```

## M4：质量验收与真实反馈迭代

预计 60 分钟。目的：把可运行功能变成可信的比赛作品，补齐测试、用户洞察和“学到了什么”的证据。

退出条件：核心测试有真实结果、主要问题已修复、至少一次有真实反馈依据的调整。真实访谈需要人参与，agent 可以准备、分析和实现，不能替代参与者编造回答。

```text
请继续 Hireland 的 M4：质量验收和用户反馈迭代。先阅读适用 AGENTS.md、README.md、Doc/HANDOFF.md、Doc/01_MONOLITH_PLAN.md、比赛 PDF 和已有 evidence，检查真实代码/git 状态。保留单体架构和已完成工作；先判断 M2 是否真实完成、M3 是完成/未验证/跳过，不把文档勾选当作事实。

按计划测试核心正常、边界、失败输入：AI 匹配/不匹配/未知与证据真实性，空/超长输入，供应商超时/非法输出，缓存失效，重复保存，重启持久化，空搜索结果。M3 若存在，还检查付费正文泄漏、真实 sandbox 交易、取消、错误归属、重复确认和恢复路径。对关键业务加有价值的回归测试，浏览器验证完整旅程；查询框架/API 细节时遵循 AGENTS.md。

读取真实匿名用户反馈，验证一个明确假设，基于证据完成至少一项小范围产品调整。若无反馈，准备短任务与提纲，清楚请求团队采集真实回答，同时继续独立测试；不得编造参与者、原话、时间节省或付费意愿。没有用户数据时准确记录该验收尚未完成。

修复阻断问题与误导性文案，检查 synthetic/社区未经核实/分数非录用概率/sandbox 标签，以及 loading、失败、重试、空态。不要扩展爬虫、上传、通知或重构技术栈。整理 Doc/evidence 下的测试结果、AI 质量、用户反馈→修改记录、数据来源，区分真实结果、模拟故障和未执行项。

更新 Doc/HANDOFF.md：已修复问题、实际检查命令与结果、证据路径、残余问题和 M5 入口。缺少真实证据不能声明全部通过。验证后直接本地 commit，不自动推送或部署，完成当前阶段后停止。
```

## M5：可复现交付与演示冻结

预计 60 分钟。目的：换机器、换账号也能启动，并让评委看到完整工作流和真实证据。

退出条件：隔离干净环境复现有记录，演示材料与实际功能一致，核心证据齐备，已完成两次彩排或清楚列明待人工执行步骤。

```text
请继续 Hireland 的 M5：冻结功能并完成比赛交付。先阅读适用 AGENTS.md、README.md、Doc/HANDOFF.md、Doc/01_MONOLITH_PLAN.md、比赛 PDF 和 evidence；检查代码/git 状态，识别真正完成的功能、未验证项和 M3 是否跳过。不要添加 P1 功能或重建架构。

在不改坏当前工作区的隔离目录中，用最新交付源码和锁文件验证 README 的安装、环境变量、数据库迁移、seed、构建与启动；包含必要未提交源码，不把遗漏它们的旧 clone 当成当前版本。只能有一个业务应用。保留现有数据库、付款权益及证据，不做自动破坏性 reset。验证缺密钥时仍能启动非外部功能并清晰提示配置缺失。需要查询 CLI/框架用法时按 AGENTS.md 查当前文档。

完成两次完整演示彩排：用户问题与真实反馈→虚构 CV/岗位→真实 OpenRouter 建议和证据→申请状态；M3 真正完成才加入 sandbox 成功交易与解锁。写建议 4 分钟讲稿、运行检查单、故障备份方案，并明确该时长不是 PDF 要求。尽可能录制真实操作备份；工具不支持或需人工时标明待完成，不虚构录屏或彩排。

逐项对照比赛：首批用户、一个完整流程、真实 OpenRouter、用户假设与所学、正常/边界/失败测试、数据来源；Stripe 若参加，核对非零价格、API Checkout、成功 sandbox 付款、产品内购买结果。不得把缓存/录屏说成实时调用，也不保证得分。缺少必要证据时准确列为未完成并修复可处理项。

更新 README、演示材料和 Doc/HANDOFF.md，给出最终可执行命令、环境变量名称、已验证功能、证据索引、已知限制、尚需人工步骤与里程碑真实状态。只修阻断问题，验证后直接本地 commit，不自动推送、发布或部署；结束时说明是否具备演示条件。
```

## 阶段中途换账号

无需硬切下一个里程碑。复制同一个阶段的 prompt，在开头加：

```text
这是阶段中途续作。请先按 Doc/HANDOFF.md 对照实际代码和 git diff，验证已完成部分，只继续剩余工作。不要清空或重写已有实现。如果交接记录落后于代码，先修正记录并说明证据。完成当前里程碑后再交接。
```

如缺少整个仓库或关键计划文件，新 agent 应先请求提供缺失文件，不能声称已理解或验证其内容。完整 prompt + 最新源码 + 据实维护的 HANDOFF，才是可持续的交接单元。
